**ТЕХНИЧЕСКОЕ ЗАДАНИЕ**

**Финальный проект курса .NET**

«CodeTrail» --- платформа для изучения программирования

  -----------------------------------------------------------------------
  **Параметр**      **Значение**
  ----------------- -----------------------------------------------------
  Исполнитель       1 студент (индивидуально)

  Срок              14 календарных дней, ориентировочно 60--70 часов

  Бэкенд            ASP.NET Core 8 Web API, EF Core (Code First),
                    PostgreSQL или SQLite

  Фронтенд          React 18 + TypeScript (Vite) или Blazor WebAssembly
                    --- на выбор

  Результат         Один Git-репозиторий с работающим приложением и
                    README
  -----------------------------------------------------------------------

*Тема выбрана так, чтобы проект не сводился к набору CRUD-форм. Основная
ценность --- в бизнес-логике: последовательная разблокировка уроков,
серверная проверка ответов, подсчёт прогресса, опыта и серии дней. При
этом объём укладывается в две недели.*

**1. Описание и роли**

CodeTrail --- учебная платформа, на которой студент записывается на
курс, читает теорию по урокам и проходит тесты. Уроки открываются по
порядку, за успешные прохождения начисляется опыт, ведётся серия
активных дней и общий рейтинг.

  -----------------------------------------------------------------------
  **Роль**          **Возможности**
  ----------------- -----------------------------------------------------
  Гость             Каталог курсов, страница описания курса, регистрация
                    и вход

  Студент           Всё выше + запись на курс, прохождение уроков и
                    тестов, свой прогресс, профиль, рейтинг

  Автор /           Всё выше + CRUD курсов, уроков и вопросов, статистика
  Администратор     по студентам
  -----------------------------------------------------------------------

Первый администратор создаётся сидированием при старте приложения.
Регистрация через API всегда создаёт роль «Студент».

**2. Модель данных**

Подход --- Code First. Миграции обязательно коммитятся в репозиторий.

  ---------------------------------------------------------------------------
  **Сущность**       **Поля**
  ------------------ --------------------------------------------------------
  User               Id, Email (unique), PasswordHash, DisplayName, Role,
                     TotalXp, CurrentStreak, LastActivityDate, CreatedAt

  Course             Id, Title (unique), Slug, Description, Level
                     (Beginner/Intermediate/Advanced), Language, IsPublished,
                     AuthorId

  Lesson             Id, CourseId, Order, Title, TheoryMarkdown, XpReward

  Question           Id, LessonId, Order, Type
                     (SingleChoice/MultiChoice/ShortAnswer), Text,
                     CodeSnippet (nullable), Explanation

  AnswerOption       Id, QuestionId, Text, IsCorrect

  ShortAnswerKey     QuestionId, ExpectedAnswer, IsCaseSensitive

  Enrollment         Id, UserId, CourseId, EnrolledAt, CompletedAt (nullable)

  LessonAttempt      Id, UserId, LessonId, StartedAt, FinishedAt,
                     ScorePercent, IsPassed, AttemptNumber

  AnswerSubmission   Id, AttemptId, QuestionId, GivenAnswer, IsCorrect
  ---------------------------------------------------------------------------

Ограничения на уровне БД: уникальные индексы на Email, Course.Title и
Course.Slug; составной уникальный индекс на (CourseId, Order) и (UserId,
CourseId). Каскадные удаления настраиваются осознанно, а не по
умолчанию.

Сидирование при старте: 2 курса по 4--5 уроков с реальным текстом теории
и осмысленными вопросами всех трёх типов. Пустые «Lesson 1 / Lesson 2»
не принимаются --- контент должен быть достаточным, чтобы проверяющий
мог реально пройти курс.

**3. Бизнес-правила**

Это ядро проекта и главный предмет проверки. Каждое нарушение возвращает
осмысленный ответ с кодом 400, 403 или 409 и понятным сообщением. Ответ
500 на некорректный пользовательский ввод считается дефектом.

1.  Уроки открываются последовательно: урок с Order = N доступен только
    если урок N−1 пройден. Первый урок доступен сразу после записи на
    курс.

2.  Урок считается пройденным при результате 70 % и выше.

3.  Проходить уроки можно только по тому курсу, на который у
    пользователя есть запись (Enrollment).

4.  Повторные попытки разрешены, но опыт (XP) начисляется только за
    первое успешное прохождение урока.

5.  Не более 5 попыток одного урока в сутки на пользователя.

6.  Курс считается завершённым, когда пройдены все его уроки ---
    проставляется CompletedAt.

7.  Правильные ответы никогда не передаются на клиент до отправки
    решения. Ответ GET /api/lessons/{id} не содержит IsCorrect и
    ExpectedAnswer. Проверка выполняется только на сервере.

8.  Серия дней (streak): +1, если предыдущая активность была вчера;
    сброс в 1, если день пропущен; без изменений при повторной
    активности в тот же день.

9.  Нельзя опубликовать курс без хотя бы одного урока, а урок --- без
    хотя бы одного вопроса.

10. Нельзя удалить урок или вопрос, по которым уже есть попытки: либо
    запрет, либо мягкое удаление.

11. Ответ типа ShortAnswer сравнивается после обрезки пробелов и
    нормализации внутренних пробелов; чувствительность к регистру
    определяется флагом IsCaseSensitive.

12. Обновление попытки, прогресса, опыта и серии дней выполняется в
    одной транзакции.

**4. Контракт API**

Ниже минимальный обязательный набор. Дополнительные эндпоинты
допускаются.

  ---------------------------------------------------------------------------------------
  **Метод**   **Путь**                                                **Доступ**
  ----------- ------------------------------------------------------- -------------------
  POST        /api/auth/register                                      Все

  POST        /api/auth/login                                         Все

  GET         /api/auth/me                                            Авторизованные

  GET         /api/courses?level=&language=&search=&page=&pageSize=   Все

  GET         /api/courses/{slug}                                     Все

  POST        /api/courses/{id}/enroll                                Студент

  GET         /api/lessons/{id}                                       Студент (если
                                                                      разблокирован)

  POST        /api/lessons/{id}/attempts                              Студент

  GET         /api/attempts/{id}                                      Владелец попытки

  GET         /api/me/progress                                        Студент

  GET         /api/leaderboard?period=week\|all                       Все

  CRUD        /api/admin/courses, /api/admin/lessons,                 Администратор
              /api/admin/questions                                    

  GET         /api/admin/courses/{id}/stats                           Администратор
  ---------------------------------------------------------------------------------------

**Ключевые эндпоинты**

-   GET /api/courses/{slug} --- возвращает описание курса и оглавление,
    где у каждого урока указан статус: passed / available / locked.
    Статус вычисляется на сервере.

-   GET /api/lessons/{id} --- теория в Markdown и вопросы без признаков
    правильности. Если урок заблокирован --- 403 с пояснением.

-   POST /api/lessons/{id}/attempts --- главный эндпоинт. Принимает
    массив ответов на все вопросы урока, проверяет их, считает процент,
    сохраняет попытку, обновляет прогресс, опыт и серию дней. Возвращает
    результат с разбором по каждому вопросу и пояснениями.

**5. Требования к бэкенду**

**Архитектура**

-   Разделение на слои: Api (контроллеры, DTO) → Application (сервисы,
    бизнес-логика) → Domain (сущности) → Infrastructure (DbContext,
    доступ к данным).

-   Контроллеры тонкие: валидация модели, вызов сервиса, возврат
    результата. Бизнес-логики и обращений к DbContext в контроллерах
    нет.

-   DTO на вход и на выход. Сущности EF наружу не отдаются --- это
    особенно критично из-за правила о неутечке правильных ответов.

-   Проверка ответов реализуется через интерфейс IAnswerChecker с
    отдельной реализацией на каждый тип вопроса, регистрируемой в DI.
    Одна большая конструкция switch по типу вопроса не принимается.

**Качество и надёжность**

-   Валидация входных данных: FluentValidation или DataAnnotations.

-   Глобальный обработчик исключений (middleware или IExceptionHandler),
    формат ответа --- ProblemDetails.

-   Логирование ключевых операций и всех необработанных ошибок (Serilog
    или встроенный ILogger).

-   Пагинация, сортировка и фильтрация на списочных эндпоинтах. Ответ
    содержит общее количество элементов.

-   Асинхронность: все обращения к БД через async/await, без .Result и
    .Wait().

**Безопасность**

-   Аутентификация по JWT, срок жизни токена задаётся конфигурацией.

-   Пароли хранятся только в виде хеша (BCrypt или PasswordHasher\<T\>).
    Пароль в открытом виде не хранится и не логируется.

-   Авторизация по ролям через атрибуты плюс проверка владения ресурсом
    в сервисе: чужую попытку посмотреть нельзя.

-   Секреты (строка подключения, ключ подписи JWT) --- через
    user-secrets или переменные окружения. В репозиторий не коммитятся.

-   CORS настроен только на адрес фронтенда, не AllowAnyOrigin.

**Тестирование**

Минимум 10 модульных тестов (xUnit или NUnit; Moq или EF Core InMemory).
Обязательно покрыты:

-   разблокировка следующего урока после успешного прохождения
    предыдущего;

-   порог 70 % --- граничные случаи 69 / 70 / 71;

-   начисление опыта только за первое успешное прохождение;

-   логика серии дней: активность вчера, позавчера, сегодня повторно;

-   проверка ответов всех трёх типов, включая нормализацию текста в
    ShortAnswer;

-   лимит попыток в сутки.

**Документация API**

-   Swagger подключён и настроен, включая кнопку Authorize для передачи
    JWT.

-   Все эндпоинты вызываются и проверяются через Swagger без
    дополнительных инструментов.

**6. Требования к фронтенду**

**Страницы**

  -----------------------------------------------------------------------
  **Страница**        **Содержание**
  ------------------- ---------------------------------------------------
  Вход / Регистрация  Формы с клиентской валидацией и выводом серверных
                      ошибок

  Каталог курсов      Карточки курсов, фильтры по уровню и языку, поиск,
                      пагинация

  Страница курса      Описание, оглавление уроков со статусами (пройден /
                      доступен / заблокирован), кнопка «Записаться»,
                      полоса прогресса

  Урок                Теория из Markdown с подсветкой кода, ниже --- тест
                      с вопросами и кнопкой «Проверить»

  Результат попытки   Процент, разбор по каждому вопросу с пояснением,
                      кнопки «Пройти ещё раз» и «Следующий урок»

  Профиль             Опыт, серия дней, курсы в процессе и завершённые

  Рейтинг             Топ пользователей за неделю и за всё время

  Админка             CRUD курсов, уроков и вопросов; статистика по курсу
  -----------------------------------------------------------------------

**Обязательные технические моменты**

-   JWT сохраняется и автоматически подставляется в заголовки запросов;
    при ответе 401 --- разлогин и редирект на вход.

-   Защищённые маршруты: неавторизованный пользователь не попадает на
    страницы студента, студент --- в админку. Админские пункты меню
    скрыты по роли.

-   Единый API-клиент (например, экземпляр axios или типизированная
    обёртка над fetch). Вызовы fetch вразброс по компонентам не
    принимаются.

-   Явные состояния интерфейса: загрузка, ошибка, пустой список. Белых
    экранов и бесконечных спиннеров быть не должно.

-   Клиентская валидация форм до отправки на сервер.

-   Минимальная адаптивность: интерфейс работоспособен и на десктопе, и
    на телефоне.

**9. Критерии приёмки**

Проект принимается, если проверяющий по README поднимает его не более
чем за 10 минут и полностью проходит следующий сценарий:

1.  Регистрация нового пользователя и вход в систему.

2.  Открытие каталога, фильтрация по уровню, переход на страницу курса.

3.  Запись на курс.

4.  Попытка открыть третий урок напрямую по ссылке --- доступ запрещён с
    понятным сообщением.

5.  Прохождение первого урока с результатом ниже 70 % --- урок не
    засчитан, следующий не открылся.

6.  Повторное прохождение с результатом выше порога --- урок засчитан,
    второй урок открылся, опыт вырос.

7.  Просмотр профиля: обновлённый опыт и серия дней.

8.  Вход под администратором, создание нового курса с уроком и
    вопросами.

**Чек-лист сдачи**

-   Один Git-репозиторий, не менее 15 осмысленных коммитов (не один
    коммит «final»).

-   README содержит: стек, требования к окружению, как поднять БД и
    применить миграции, как запустить бэкенд и фронтенд, тестовые
    учётные записи.

-   Миграции применяются с нуля на чистой базе одной командой.

-   Команда dotnet test проходит без ошибок.

-   На странице урока в инструментах разработчика браузера правильные
    ответы не видны.

-   Приложение не возвращает 500 на некорректный пользовательский ввод.

-   В репозитории нет секретов, а также папок bin, obj, node_modules.
